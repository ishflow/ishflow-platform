# 1CAnalog Performance Audit — 2026-05-13

> Audit run on `feat/performance-audit-fixes` (worktree `.worktrees/perf-audit`).
> The headless runtime audit (`pnpm audit:perf`) requires a captured Clerk
> session (Playwright `storageState`). Overnight automated runs without a
> human-attended sign-in step have no way to acquire that session, so this
> report is derived from a static read of every code path the top-10 routes
> exercise. The runtime tooling is committed in `scripts/perf/` and can be
> exercised any time after `pnpm tsx scripts/perf/login-once.ts`.

## Methodology

- Read every list and detail entrypoint under `app/[locale]/(platform)/**`
  for the top-10 routes.
- Traced each one into `platform/engine/*` and `platform/auth/*` to find
  every Prisma roundtrip + every `withTenant` opening.
- Cross-checked indexes in `prisma/schema.prisma` against the `WHERE`
  clauses observed in the engine layer.
- Confirmed dashboard widget topology: 18 widgets, each its own Suspense
  boundary, each calling `requireTenantContext()` independently.

## Ranked top problems

1. **Per-widget `requireTenantContext()` duplication on `/dashboard`**
   - **Where:** every file under `lib/dashboard/widgets/*.tsx`. Each is its
     own server component, wrapped in `<Suspense>` from `app/[locale]/(platform)/dashboard/page.tsx`,
     and each calls `requireTenantContext()` inside its body.
   - **Cost:** 18 widgets × (1 Clerk session lookup + 1 `Tenant.findUnique`)
     per render. The work is identical every time, but React's render cache
     is not engaged because the function is a plain async function.
   - **Fix:** wrap `resolveContext` body in `react.cache()` so the cache
     dedupes within a single request render.

2. **KPI helpers (`accountsReceivableTotal`, `accountsPayableTotal`, etc.)
   stream every movement row to JS just to sum it**
   - **Where:** `platform/engine/dashboard-queries.ts`. Both functions
     do `findMany({ where, select: { kind, amount } })` then JS reduces by
     `kind === 'income' ? + : -`.
   - **Cost:** O(n) memory + transfer for n movement rows per snapshot;
     two snapshots (current + previous) per KPI; 4–6 KPIs touched.
   - **Fix:** replace with `groupBy({ by: ['kind'], _sum: { amount: true } })`
     and reduce the 2-row result set, not the full table.

3. **Missing `(tenantId, timestamp)` index on all 4 movement tables**
   - **Where:** `prisma/schema.prisma` lines 740–825. The existing indexes
     are `(tenantId)`, `(tenantId, active)`, `(tenantId, docRef)`, and a
     domain-specific composite `(tenantId, <dim>, <dim>, timestamp)`.
     The dashboard KPI and turnover queries filter `WHERE tenantId AND
     timestamp <= X` (or `>= X`) without selecting the leading dimension,
     so the composite index is unusable. Postgres then falls back to the
     low-cardinality `(tenantId)` or `(tenantId, active)` index and
     scans every matching row.
   - **Cost:** scales linearly with movement table size. A demo tenant
     with 10k movements per table is sluggish; a real tenant will be
     unusable.
   - **Fix:** additive `(tenantId, active, timestamp)` composite on each
     of the four movement tables. Use `(active, timestamp)` ordering so
     the dashboard's `WHERE active=true AND timestamp <= X` is fully
     index-served.

4. **`enrichDocumentListRows` scatters Prisma roundtrips across multiple
   `withTenant` blocks**
   - **Where:** `platform/engine/document-list-enrich.ts`. Reads the
     code: each catalog ref token (`customer`, `supplier`, etc.) opens
     a new `withTenant`; each line section (`lines`, `expenses`, etc.)
     does the same.
   - **Cost:** per-page list rendering does (refTokens + lineSections)
     tx-opening overhead, each one paying the RLS GUC roundtrip
     (`set_config('app.tenant_id', ...)`).
   - **Fix:** open ONE `withTenant` wrapping a `Promise.all` of all the
     `findMany` calls.

5. **`getPresentationsForRefs` opens one `withTenant` per typeId group**
   - **Where:** `platform/engine/presentation-batch.ts`. The function
     correctly batches refs by typeId, but each per-typeId
     `getPresentationsByRefs` call is its own `withTenant` unless the
     caller pre-opens one and passes `opts.tx`.
   - **Cost:** for a 25-row list page with 4 ref columns (e.g. products
     with category + group + priceType + uom), that's 4 separate RLS
     GUC roundtrips per page.
   - **Fix:** on the list pages that call this helper, wrap the call in
     a single `withTenant` and pass `tx` through `opts`.

## What actually shipped (post-fix update)

Static analysis ran ahead of the fixes; two of the original top-5
turned out to be **already** addressed in source:

| Problem | Status | Notes |
| --- | --- | --- |
| 1. Per-widget `requireTenantContext()` duplication | **already fixed** | `resolveContext` (line 144 of `platform/auth/current-context.ts`) is wrapped in `react.cache()`; widget calls dedupe within a single render. |
| 2. KPI helpers stream rows for in-memory reduce | **fixed** (commit `a7092f8f0`) | `accountsReceivableTotal` + `accountsPayableTotal` now use `groupBy({ by: ['kind'] })` inside `Promise.all`. |
| 3. Missing `(tenantId, active, timestamp)` index on movement tables | **fixed** (commit `850d6d381`) | Generator emits the index; hand-written migration `20260513210000_perf_indexes` applies it to all four movement tables. |
| 4. `enrichDocumentListRows` scatters Prisma roundtrips | **already fixed** | The helper opens a single `withTenant` at line 138 and runs ref + line-section lookups in `Promise.all` inside it. |
| 5. `getPresentationsForRefs` opens one `withTenant` per typeId | **fixed** (commit `349f5a05f`) | Catalog list page + `widget-posting-effects` now wrap the call in a single `withTenant` and pass `{ tx }` through opts. |

### Bonus optimizations (commit `3b5f72622`)

Two additional issues surfaced while applying the top-5 fixes:

- **6. Sequential `await` pairs in dashboard KPI helpers.**
  `thisMonthSalesTotal`, `openInvoiceCount`, `last30DaysTrend`,
  `upcomingReceivables`, and `upcomingPayables` each ran two
  independent Prisma queries one after the other. They now run as
  `Promise.all` pairs.

- **7. `findMany + JS reduce` for customer/supplier A/R + A/P balances.**
  `upcomingReceivables` and `upcomingPayables` were streaming every
  movement row and bucketing per-customer/per-supplier in JS. They now
  use `groupBy({ by: ['customer', 'kind'] })` (resp. supplier) so
  Postgres returns one row per (counterparty, kind) instead.

## Notes

- All fixes are additive (no destructive migrations, no DSL changes,
  no RLS tweaks).
- The composite-index migration was hand-written under
  `prisma/migrations/20260513210000_perf_indexes/migration.sql`
  because `pnpm generate` triggers known pre-existing drift on
  `markupPct` and camelCase `@map`s — tracked separately under
  generator drift on camelCase refs (the Prisma generator strips `@map`). The
  generator emit was updated in the same commit so the index re-emits
  the next time the unrelated drift is fixed.
- Regression tests in Phase 3 lock the dashboard, list, and detail at
  bounded query counts.
- The runtime audit toolkit (`scripts/perf/*.ts`) is committed and ready
  for the next operator-attended run; once `PERF_AUDIT_STORAGE_STATE`
  is captured, `pnpm audit:perf` will overwrite this report with live
  numbers.
